# @matteophre/nestjs-pagina-me

NestJS integration for [@matteophre/pagina-me](https://github.com/matteoPhre/pagina-me). It normalizes pagination query parameters, validates limits, and provides a service for creating and verifying HMAC-signed cursors.

## Installation

```bash
pnpm add @matteophre/nestjs-pagina-me @matteophre/pagina-me
```

## Configuration

Import the module once in the root module. Keep the secret server-side and stable; changing it invalidates existing cursors.

```ts
import { Module } from '@nestjs/common';
import { PaginationModule } from '@matteophre/nestjs-pagina-me';

@Module({
  imports: [
    PaginationModule.forRoot({
      secret: process.env.CURSOR_SECRET!,
      defaultLimit: 20,
      maxLimit: 100,
    }),
  ],
})
export class AppModule {}
```

Use `PaginationModule.forRootAsync({ imports, inject, useFactory })` when the configuration depends on Nest providers.

## Controller

`@Paginate()` exposes the HTTP query parameters and `PaginationPipe` converts them into a typed `PaginationQuery`. The pipe applies the default limit, rejects non-integer limits and limits over `maxLimit`, and prevents using `after` and `before` together.

```ts
import { Controller, Get, UsePipes } from '@nestjs/common';
import {
  Paginate,
  PaginationPipe,
  type PaginationQuery,
} from '@matteophre/nestjs-pagina-me';

@Controller('users')
export class UsersController {
  @Get()
  @UsePipes(PaginationPipe)
  findAll(@Paginate() query: PaginationQuery) {
    // query: { after: string | null, before: string | null, limit: number }
  }
}
```

The default parameter names are `after`, `before`, and `limit`. Change them with `paramNames` in `forRoot` or `forRootAsync`.

## PaginationService

The injected service exposes `forwardQuerySpec`, `backwardQuerySpec`, `createCursor`, `decodeCursor`, `reorderBackward`, `buildPaginationState`, and `buildPageInfo`. Use the query-spec methods when building a database query, then return the state generated by `buildPaginationState`.

### Cursor Integrity

`createCursor(payload)` serializes the payload and signs its contents with the module secret. The resulting opaque `pme:` value is safe to expose to clients, but it must be treated as an opaque value: clients must send it back unchanged.

`decodeCursor(cursor)` verifies the signature before returning a payload. It returns `null` for a missing or empty cursor. It throws `CursorTamperedError` when a valid-looking cursor was modified or verified with a different secret, and `InvalidCursorError` when the cursor does not have the expected format. Map these errors to a `400 Bad Request` response when cursors come from an HTTP request.

Do not rotate the secret without a migration strategy: every cursor signed with the previous secret becomes invalid. Never derive the secret from user input or expose it in client-side code.
